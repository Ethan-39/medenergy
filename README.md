# MedEnergy: Energy Forecasting and Carbon-Aware Scheduling

一个用于学习能源预测、光伏利用和碳排放情景调度的可运行教学原型。它把医院场景当作讲解载体，但不使用临床数据，也不是医院控制系统。

## 项目亮点

- 用时间顺序切分训练集和测试集，避免把未来数据泄露给模型
- 用简单线性回归预测背景负荷，并和“昨天同一时刻”基线比较
- 在任务释放时间、截止时间和最大移动范围内枚举可行开始时间
- 用模拟电价、光伏和碳因子评估购电费用与碳排放情景
- 用约束检查保证任务时长、截止时间和总能量守恒

项目中的医院负荷、光伏、电价、碳因子和灭菌任务均为教学仿真。结果应表述为“仿真原型结果”，不能写成真实医院验证的节能效果。

你已经拿到一份可以运行、修改、演示的项目。先看见结果，再逐步理解算法。

## 第 1 步：先打开成品（约 2 分钟）

双击本文件夹中的 `dashboard.html`。不需要安装 Python、注册账号或联网。

你应该能看到：

1. 当天购电费用、购电碳排和峰值功率。
2. 模拟实测负荷与 AI 预测负荷两条曲线。
3. 固定排程与优化排程的购电曲线。
4. 两个模拟灭菌任务的原开始时间、优化开始时间和截止时间。

如果页面里没有数字或曲线，请用 Edge 或 Chrome 打开。不要把 `dashboard_template.html` 当成成品打开；它是生成页面用的模板。

## 第 2 步：动三个控件（约 5 分钟）

按这个顺序操作：

1. 保持第一天 `2026-09-25`，把“允许任务前后移动”设为 **0 小时**。固定与优化曲线应重合，费用和碳排变化应为 0%。这就是你的对照组。
2. 改为 **4 小时**。观察任务开始时间、费用、碳排和光伏自用量发生什么变化。
3. 切换到周末日期。当天没有模拟灭菌任务，优化与固定排程一致。
4. 调整“碳排偏好”。不是每次调整都会改变时间：候选方案相同时，最优方案也可能相同。

重要：这版做的是移峰，完整任务量不变。设备总用电量应该相同；由于时段和光伏自用量变化，电网购电及其费用、碳排可能下降。实际仿真结果可能有改善，也可能没有，不预设节能比例。

## 第 4 步：做你的第一次修改（约 10 分钟）

用记事本或代码编辑器打开 `config.json`。只改一个值：

```json
"pv_capacity_kw": 300
```

把 **300 改成 150**，保存，然后双击 `run.cmd`。

比较“光伏出力”和“光伏自用”。这就是第一次真正修改系统参数并看到结果。

第二个实验：把 `max_shift_hours` 从 4 改成 0，再运行。调度方案应退回固定排程。做完恢复为 4。

配置说明：

| 参数 | 意义 | 初始值 |
| --- | --- | --- |
| days | 生成多少天数据 | 30 |
| training_days | 前多少天用于训练，剩余用于测试 | 24 |
| seed | 固定随机种子，相同参数重跑可复现 | 17 |
| pv_capacity_kw | 模拟光伏装机参数，实际出力受时段与云量影响 | 300 |
| sterilizer_power_kw | 每批模拟灭菌任务的运行功率 | 32 |
| sterilizer_duration_minutes | 连续运行时长，可用 15/30/45/60 分钟 | 45 |
| max_shift_hours | 相对固定排程允许前后移动多久，0～6 | 4 |
| carbon_weight_yuan_per_kg | 把碳排加入目标的偏好权重，非真实碳交易价格 | 0.4 |

## 第 5 步：看懂数据（约 15 分钟）

用 Excel、记事本或代码编辑器打开 `data/hospital_energy.csv`。共有 **30 × 96 = 2880 行**，每行对应 15 分钟。

先只看这些列：

| 列名 | 中文意义 |
| --- | --- |
| timestamp | 时间 |
| forecast_temperature_c | 提前可获得的模拟天气预报 |
| planned_occupancy_ratio | 提前可获得的计划占用率 |
| actual_background_kw | 固定医疗负荷、空调和照明的实际合计功率 |
| baseline_task_kw | 灭菌任务按固定排程运行的功率 |
| actual_total_kw | 总实际功率 = 背景负荷 + 灭菌任务 |
| pv_forecast_kw / pv_actual_kw | 预测光伏 / 模拟实际光伏功率 |
| tariff_yuan_per_kwh | 模拟电价 |
| carbon_kg_per_kwh | 模拟电网碳因子 |

**kW 是功率，kWh 是电量。** 本版每行的用电量 = 功率 × 0.25 小时。例如 32 kW 连续运行 45 分钟，耗电是 32 × 0.75 = 24 kWh。

不需要先理解 CSV 的每一列，也不需要先学习深度学习。

## 第 6 步：按顺序读代码（分两天完成）

全部核心代码在 `medenergy.py`，按下列顺序看：

1. `generate_data()`：怎样生成医院背景负荷、光伏、电价和碳因子。
2. `features()`：给 AI 的输入是什么。只包含提前可获得的模拟预报、计划占用率、固定影像预约等。
3. `fit_linear_regression()` / `predict()`：从前 24 天学出关系，预测后 6 天。它是最基础的机器学习模型“线性回归”，加了很小的岭惩罚。
4. `optimize_day()`：每隔 15 分钟尝试一个合法开始时间，计算“购电费 + 碳偏好 × 碳排”，选最小的候选。
5. `evaluate_day()`：用模拟实际负荷与实际光伏回放评估，避免只看乐观预测值。
6. `verify_plan()`：检查任务不能消失、不能缩短、不能中断、不能过期、不能在同一灭菌器上重叠。

本版两个任务窗口互不重叠，所以可以各自枚举。更多设备共用资源时，需要升级为约束优化；当前算法不能直接当作完整医院调度器。

训练/测试按时间切分。所有测试日都不用于模型训练。“昨天同一时刻”仅作为逐日预测的对照基线；不是 AI 输入。

## 文件对应什么

```text
MedEnergy/
├── README.md                     这份新手教程
├── config.json                   你先修改这里
├── run.cmd                       双击重新生成全部结果
├── medenergy.py                  数据 + 预测 + 调度 + 评估
├── dashboard_template.html       页面模板
├── dashboard.html                直接打开的成品
├── data/hospital_energy.csv      30 天仿真数据
└── results/
    ├── predictions.csv           后 6 天预测结果
    ├── schedules.csv             默认配置的调度结果
    └── evaluation.json           预测误差、汇总结果、约束检查
```

## 跑通后才做的升级

1. 第 2 版：用 scikit-learn 或 XGBoost 替换当前线性回归，沿用时间切分和同样的误差指标比较。
2. 第 3 版：用 OR-Tools 加入更多任务、资源占用及电池约束。电池需要效率、容量及期末电量约束。
3. 第 4 版：把静态看板改成 Streamlit，再尝试接入真实数据。

这份数据、设备功率、任务窗口、电价及碳因子都是教学仿真。比赛中写“仿真原型结果”；不要写成真实医院验证的节能效果。本版仅移动模拟灭菌批次，MRI/CT 预约和其他负荷保持固定。
